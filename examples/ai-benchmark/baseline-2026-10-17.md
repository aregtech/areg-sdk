# Baseline, 2026-10-17: areg and gRPC with Claude Sonnet 5.5 at low effort

Three tasks, written after the earlier baselines: a camera pipeline, a charge point with
a state machine, and a sensor gateway. Claude Code with Sonnet 5.5 at `low` effort. It
sits beside [`baseline-2026-10-05.md`](baseline-2026-10-05.md) (GPT-5.6 Terra) and
[`baseline-2026-09-29.md`](baseline-2026-09-29.md) (Sonnet 5.5, medium effort).

| **model** | `claude-sonnet-5-5` | same |

| tasks | [`prompt-camera.md`](prompt-camera.md), [`prompt-chargepoint.md`](prompt-chargepoint.md), [`prompt-sensorgateway.md`](prompt-sensorgateway.md) | same requirements and checklist |
| what the agent may read | a copy of this repository | the task and the scenario runner |
| framework | areg, compiled from that copy inside the run | gRPC 1.51.1, protobuf 3.21.12, system packages |
| repository revisions | `09979beb` to `e3b0a2ca` (see below) | `b0431d06`, `c8486ec8` (the gRPC arm reads only the task and the runner) |
| web | off | on |
| prompt cache | 1 hour | same |
| toolchain | GCC 15.2.0, CMake 4.2.3, C++17 | same |
| machine | Linux under WSL2 | same |
| runs | 2026-10-16 and 2026-10-17 | 2026-10-15 and 2026-10-17 |

**The areg revisions.** The areg runs span five consecutive revisions. Between them, the
text an agent reads changed by 21 bytes, and two tool defects were fixed (one of them
made one run wait about 25 minutes). The runs are reported together, and per run in
the ranges.

**Cost** is recomputed from each transcript at list price ($2 input, $0.20 cache read,
$4 one-hour cache write, $10 output per million tokens), for a cold cache. Claude Code's
own total charges cache reads at half that rate; on that basis both arms are lower and
areg's gap to gRPC widens by 2-4 points, because areg reads more cached context.
**C++ written by hand** is, for areg, every body line the agent wrote into the generated
application's markers (`bodies.txt`, comments and blank lines excluded); for gRPC, every
non-blank line of C++ in the project outside the build directory and the generated stubs.

The probe `checked` (a printed task line states only values its step bodies compared)
reads `bodies.txt`, so it applies to the areg arm only. The 2026-10-15 gRPC runs were
first scored by an earlier verifier that did not apply `timing`; re-scored on 2026-10-17
with the current one, each passes 8 of 8. The CPU rows were measured on 2026-10-17 for one
run of each arm and task, one after another on an idle machine: the first scoring of the
gRPC runs gave 0.15-0.32 cores under other load, so this probe moves with the machine.

- **Correctness.** Every areg run passed every hidden probe. One of the two gRPC
  chargepoint runs failed `peer-loss`: with the driver killed a quarter of the way in, the
  manager never exited. The other gRPC runs passed every probe they were scored on.
- **Fix cycles.** areg: none in 13 of 14 runs; one run paid one, a refused tool option
  that named the right one. gRPC: 4 on camera, 4 and 2 on chargepoint, 1 on sensorgateway.
- **Cost.** At parity on all three: camera +1% at the median, sensorgateway +0.5%, and on
  chargepoint areg's median $1.225 lies between the two gRPC runs ($1.118 and $1.477), 6%
  below their mean. With one or two gRPC runs per task, none of these differences is a
  result.
- **Spread.** The two gRPC chargepoint runs were 32% apart in cost; the seven clean areg
  runs, on five revisions, 15%.
- **Hand-written C++.** 2.3-4x less with areg, because the generator writes the
  components, the model, `main()`, the CMake and the scenario driver.
- **CPU.** Measured side by side, areg programs used 0.01-0.03 cores over a normal run,
  the gRPC programs 0.02-0.11. In two of the three tasks the gRPC programs polled for
  cancellation every 200-250 ms; that costs little CPU, but it is a wake-up an idle
  areg program does not make.
- **Time.** areg took less wall time on every task: 5.6-6.6 min against 7.1 on camera,
  7.3-8.7 against 9.3 and 25.8 on chargepoint, 3.9-4.6 against 5.1 on sensorgateway. Of
  the 25.8 minutes, 10 were one filesystem search (`find /`) that hit the command timeout.
- **Where areg pays more** on chargepoint: the knowledge it loads (115-145K tokens written
  to the cache, against 75K for gRPC) and more thinking (a median of 35K tokens against 29K). The
  same tree ran up to 12% apart from run to run, all of it in thinking.

cost ratio: it depends on the task and the model, from 26% below gRPC to 1% above, and
single runs of one task vary by 12-50%.

## 4. Limits

- One gRPC run on camera and sensorgateway, two on chargepoint; areg 2-8. A difference
  smaller than the ranges above is not a result.
- The areg runs span five revisions (section 1).
- The gRPC projects were built unoptimised, the areg ones optimised. That moves wall time
  and CPU, not the cost. An optimised build lowers the CPU of each wake-up, not the
  number of wake-ups a timed poll makes.
- The tasks were written by the areg side. They are multi-process services, two with a
  state machine: areg's target domain, not every gRPC user's.
