# Baseline, 2026-10-18: areg and gRPC with GPT-5.6 Terra, six tasks

Today's areg tree on six tasks with GitHub Copilot CLI and GPT-5.6 Terra, against every
gRPC run of the same tasks with the same agent and model. It extends
[`baseline-2026-10-05.md`](baseline-2026-10-05.md) (four tasks, identical prompts) with the
elevator and the sensor gateway, and replaces its areg arm with the current tree.

**The areg arm had the harder task.** The gRPC runs were made on 2026-10-04 to 2026-10-07,
and the prompts have since gained requirements, none was relaxed: every task now names the
exact line each step prints (8-10 lines, checked by the `lines` probe), adds a `(code)`
checklist item, and printscan requires a **declared** state machine with print and scan as
nested pieces entered from two places. The gRPC arm was scored on what its prompt asked.

## 1. Setup

| | areg arm | gRPC arm |
|---|---|---|
| **agent** | GitHub Copilot CLI, headless | same |
| **model** | `gpt-5.6-terra`, effort medium | same |
| fix bound | 15 build-and-fix and 15 run-and-fix cycles | same |
| tasks | [`prompt-atm-fsm.md`](prompt-atm-fsm.md), [`prompt-coffeemachine.md`](prompt-coffeemachine.md), [`prompt-tempalarm.md`](prompt-tempalarm.md), [`prompt-printscan.md`](prompt-printscan.md), [`prompt-elevator.md`](prompt-elevator.md), [`prompt-sensorgateway.md`](prompt-sensorgateway.md) | the same tasks as they were on the run date (+9 to +45 lines since) |
| what the agent may read | a copy of this repository | the task and the scenario runner |
| framework | areg, compiled from that copy inside the run | gRPC 1.51.1, protobuf 3.21.12, system packages |
| repository revision | `c8486ec8` (atm-fsm, printscan), `c7e420c7` (the rest); between them only two tool refusals changed | `1c7cf302`, `d877d1da`, `8e426793` |
| web | off | on |
| runs | 2026-10-17 | 2026-10-04 to 2026-10-07 |
| scoring | [`verify_run.py`](verify_run.py) | **the same verifier, re-run on 2026-10-18** |

Cost is Copilot's billed AI credits (1 AIC = USD 0.01). An API request is Copilot's
`requests.count`. Fix cycles are the agent's own report. **C++ written by hand**: for areg the
body lines in `bodies.txt`, for gRPC every non-blank C++ line outside the build directory.

One areg printscan run is left out of the medians as an outlier: the agent sent each print
twice, from its own callback and from the generated step; the device refused the second, as
the task requires, and the step failed. It cost $1.19 and 40 requests, and still passed every
probe in the end. With it, the printscan median is $0.552.

- **Correctness.** All 14 areg runs passed every probe they were scored on (6-8 each). Two of
  the 11 gRPC runs failed: a coffee machine that charged a cancelled drink when it started
  after the user, and an elevator that reported a wrong floor once in ten repeats and failed
  start-order. The re-score confirmed the original verdicts.
- **Cost.** Summed over the six task medians: areg **$2.633**, gRPC **$2.657**, for the
  harder task. Per task: atm-fsm -5%, coffee -11%, tempalarm -1%, elevator -18%;
  sensorgateway +26% and printscan +18%.
- **Requests.** Summed over the medians: areg **70.5**, gRPC **117.5** (-40%).
- **Fix cycles.** areg 27 in 14 runs (1.9 per run), gRPC 80 in 11 runs (7.3 per run).
- **Hand-written C++.** 2-3.5x less with areg. The gRPC agents hand-wrote worker threads,
  mutexes and condition variables in every task, a table-driven machine on atm-fsm, a
  `sleep_for` in a printscan client and a 200 ms timed wait loop in the elevator client.
- **Time.** Model time, summed over the medians: areg 11.3 min, gRPC 14.7 min (-23%).
  Wall time: areg 31.6 min, gRPC 26.4: every areg run compiles the framework from source,
  the gRPC arm uses prebuilt packages.
- **Spread.** About equal with this model: areg 9-48% per task, gRPC 16-70%. Two areg tasks
  spread 46-48%. Part of each spread was Copilot's own todo bookkeeping, 3-4 requests in one
  run of each, which the gRPC runs of October used far less.
- **Where areg pays more** is the context it loads: the guide and the generated worksheet.
  On the sensor gateway, the task with the fewest prompt changes, that is the whole +26%.

## 3. Limits

- 1-2 gRPC runs per task, 2-4 areg runs. A difference smaller than the ranges is not a
  result.
- The prompts differ as described above; the comparison favours gRPC on cost and cannot
  favour it on correctness.
- The gRPC projects were built unoptimised, the areg ones optimised: that moves CPU and wall
  time, not cost.
- The tasks were written by the areg side: multi-process services, most with a state
  machine.
