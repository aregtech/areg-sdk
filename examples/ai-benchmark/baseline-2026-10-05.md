# Baseline, 2026-10-05: areg and gRPC with GPT-5.6 Terra

Three areg runs and two gRPC runs on each of four tasks, with GitHub Copilot CLI and
GPT-5.6 Terra. The areg runs are all on one repository revision, the one this baseline is
committed with; earlier areg runs were made while the documentation and the tools were
still changing during the day, and are not compared. It sits beside
[`baseline-2026-09-29.md`](baseline-2026-09-29.md), which is the Claude Sonnet 5.5
comparison.

---

## 1. Setup

| | areg arm | gRPC arm |
|---|---|---|
| **agent** | GitHub Copilot CLI 1.0.91, headless | same |
| **model** | `gpt-5.6-terra` | same |
| **effort** | medium | same |
| fix bound | 15 build-and-fix and 15 run-and-fix cycles | same |
| debrief | on in every run: one extra answer at the end | same |
| tasks | [`prompt-atm-fsm.md`](prompt-atm-fsm.md), [`prompt-printscan.md`](prompt-printscan.md), [`prompt-coffeemachine.md`](prompt-coffeemachine.md), [`prompt-tempalarm.md`](prompt-tempalarm.md) | same requirements and checklist |
| what the agent may read | a copy of this repository | the task and the scenario runner |
| framework | areg, compiled from that copy inside the run | gRPC 1.51.1, protobuf 3.21.12, system packages |
| repository revision | `390cc882` | `1c7cf302` (the gRPC arm reads only the task and the runner) |
| web | off | on |
| toolchain | GCC 15.2.0, CMake 4.2.3, C++17 | same |
| machine | Linux under WSL2 | same |
| runs | 2026-10-05 | 2026-10-04 |

Started with [`run-benchmark.sh`](run-benchmark.sh). Copilot bills AI credits (AIC), and
1 AIC is USD 0.01. An API request is Copilot's own `requests.count`. **C++ written by
hand** is, for areg, every body line the agent wrote into the generated application's
markers (`bodies.txt`, comments and blank lines excluded); for gRPC, every non-blank
line of C++ in the project outside the build directory. Each arm also writes a
declaration: areg a `design.json` of 3-11 KB, gRPC a `.proto` and a `CMakeLists.txt`
of about 70 lines.

| | C++ written by hand | 106-141 lines | 326-369 lines |

- **Correctness.** All 12 areg runs passed every hidden probe. 7 of 8 gRPC runs did;
  the eighth failed `start-order`: with the client started first, its scenario reported
  "cancelled drink not charged".
- **Requests.** areg needed fewer on every task: medians 7-16 against gRPC's 12.5-20.
  The ranges overlap on atm-fsm and tempalarm.
- **Cost.** At parity on atm-fsm, and below gRPC on the other three, by 9-22% against the
  gRPC mean. That is not a significant result at three runs against two.
- **Hand-written C++.** About 2-4x less with areg on every task, because the generator
  writes the components, the model, `main()`, the CMake and the scenario driver.
- **Where the money goes.** An areg request carries about 8K more tokens of context
  than a gRPC request on average (37.6K against 29.6K) -- the documentation and the
  generated worksheet the agent reads -- so it costs 2.7-3.7 AIC against 1.9-2.9. areg spends fewer requests and pays more for
  each; the next saving is in that per-request context, not in the request count.

## 3. Limits

- Three runs per task against two. One run of a task has varied by 50% on an unchanged
  tree, so a difference smaller than the ranges above is not a result.
- The two arms ran a day apart, and the gRPC projects were built as Debug, the areg ones
  optimised. That moves wall time, which is not reported, and not the cost.
- The tasks were written by the areg side. They are multi-process services, three of
  them with a state machine: areg's target domain, not every gRPC user's.
- Copilot may load the user's own CLI configuration in both arms; see
  [`README.md`](README.md#how-the-agents-differ-in-the-harness).
