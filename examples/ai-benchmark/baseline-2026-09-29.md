# Baseline, 2026-09-29: areg and gRPC with Claude Sonnet 5.5

Four runs per framework on the coffee-machine task and one per framework on the
temperature alarm. The agent, model, effort, fix bound, machine and repository revision
were the same for both arms. It replaces [`baseline-2026-09-13.md`](baseline-2026-09-13.md)
as the current comparison. The earlier pair was made with Claude Sonnet 5, and section 4
says what changed with the model.

---

## 1. Setup

| | areg arm | gRPC arm |
|---|---|---|
| **agent** | Claude Code 2.1.284 / 2.1.285, headless (`claude -p`) | same |
| **model** | `claude-sonnet-5-5` (the `sonnet` alias from 2026-09-29) | same |
| **effort** | medium | same |
| tools allowed | Bash, Read, Write, Edit, Glob, Grep; no skills, no MCP servers | same, plus web search and fetch (none was used) |
| fix bound | 15 build-and-fix and 15 run-and-fix cycles | same |
| tasks | [`prompt-coffeemachine.md`](prompt-coffeemachine.md), [`prompt-tempalarm.md`](prompt-tempalarm.md) | same requirements and checklist |
| what the agent may read | a copy of this repository | the task and the scenario runner |
| framework | areg, compiled from that copy inside the run | gRPC 1.51.1, protobuf 3.21.12, system packages |
| repository revision | `ad705dfe` (one coffee run on `0dcac663`, which differs only in the runner's debrief wording) | `ad705dfe` |
| toolchain | GCC 15.2.0, CMake 4.2.3, C++17 | same |
| machine | Linux under WSL2, 20 threads, 15 GB | same |

Started with [`run-benchmark.sh`](run-benchmark.sh), with `--debrief` on every run but one
areg coffee run. The debrief is one extra answer at the end, about $0.02. Costs are
[`analyze_run.py`](analyze_run.py)'s `cost, cold @1h`, which adds back the discount a run
gets for starting within an hour of another, so that runs compare. The raw artefacts are
kept with the runs and are not committed.

## 2. Result, coffee machine (4 runs per framework)

| | areg | gRPC |
|---|---:|---:|
| **hidden probes passing** | **5 of 5 in every run** | **5 of 5 in every run** |
| acceptance items (agent's report) | 14 of 15 in every run | 14 or 15 of 15 |
| **cost, median** | **$0.714** | **$0.795** |
| cost, range | $0.698-0.728 (4%) | $0.678-0.894 (32%) |
| **API requests** | 8-9 | 8-13 |
| **C++ written by hand** | **386-420 lines, 6 files** | **1,252-1,411 lines, 20-30 files** |
| output tokens, median (of it thinking) | 28.8K (16.5K) | 46.1K (20.2K) |
| tokens entering the context, median | 79K | 59K |
| model time, median | 3.4 min | 5.0 min |
| build-and-fix + run-and-fix cycles | 0 in 3 runs, 1 + 1 in one (a late change after a pass) | 1 + 1 in every run |
| filesystem searches | 0 | -- |

- **Both arms produce a correct application** in every run, and the hidden probes
  confirm it: 10 clean repeats, the client started first, no peer at all, the peer killed
  at 25/50/75%, and no busy-waiting.
- **areg is cheaper at the median by 10%, but that is not a significant result at 4
  runs** (Mann-Whitney p = 0.34). The cheapest single run was a gRPC run.
- **What holds at this sample size:**
  - areg's cost varies by 4% from run to run, gRPC's by 32%;
  - every areg run took the same path with no fix cycle;
  - areg needed about 3x less hand-written C++ and 37% fewer output tokens.
- **Where the money goes is opposite in the two arms.** areg pays to read its own
  documentation: about 44K tokens, roughly $0.22 of a run, which the model does not need
  for gRPC. gRPC pays to write its plumbing (threads, shutdown, CMake, the `.proto`) as
  output, the most expensive token.
- **gRPC's fix cycles were all plumbing.** CMake failing to find protobuf on this host
  (see [`INSTALL-grpc.md`](INSTALL-grpc.md)), a repeated enum field, and a server that
  hung at exit.

## 4. What changed from Sonnet 5

The `sonnet` alias moved from `claude-sonnet-5` to `claude-sonnet-5-5` on 2026-09-29.
The list price per token is the same.

| Coffee machine | Sonnet 5 | Sonnet 5.5 |
|---|---|---|
| areg, cost median | $1.51 (6 runs, 2026-09-28/29) | $0.71 |
| gRPC, cost range | $1.30-3.19 (6 runs, 2026-09-11/13) | $0.68-0.89 |
| areg, API requests | median 26, range 16-32 (earlier corpus) | 8-9 |
| gRPC, API requests | median 55.5, range 31-90 | 8-13 |

- **Sonnet 5.5 thinks about a third as much** on the same task, and on the same Claude
  Code version the harness sends a shorter system prompt. Both arms cost about half,
  or less, of what they did.
- **With Sonnet 5, areg's lead was wider.** Its generator halved the number of API
  requests, because the gRPC agent wrote its files one request at a time. Sonnet 5.5
  writes many files in one request, so the two arms now need the same number of
  requests.
- **What did not change is what the generator removes.** The generator still writes the
  plumbing: areg's hand-written code stayed at about 400 lines, and gRPC's at
  1,250-1,400.

## 5. Limits

- Four runs per arm on one task, and one run per arm on a second task.
- The gRPC host lacked protobuf's CMake config package, which cost the gRPC arm about
  one request in 4 of 5 runs. It is fixed for later runs.
- The tasks were written by the areg side. They are two-process services with a state
  machine: areg's target domain, not every gRPC user's.
